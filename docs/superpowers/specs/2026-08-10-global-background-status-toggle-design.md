# 全窗口背景与状态面板开关图标设计

## 背景

当前自定义背景图层只挂在 `.chat-main`，因此聊天区域能够显示背景，侧栏、标题栏、设置页和历史页仍使用不透明的主题底色。聊天输入区右侧的状态面板开关虽然可以点击，但它复用了旧的 `.status-panel-toggle` 容器样式，收起状态下的图标没有可靠显示。

## 目标

- 自定义背景覆盖 ccNexus 的整个 renderer 窗口，而不是只覆盖聊天内容。
- 背景能够透过侧栏、标题栏、聊天面板和其他主要表面显示，同时使用主题遮罩保证文字可读。
- 保持现有背景选择、清除、透明度、模糊和遮罩参数的行为不变。
- 让状态面板总开关在收起和展开两种状态下都显示清晰的方向图标。
- 只使用 ccNexus 自己的外观状态，不触碰 Claude Code、cc-switch 或其他配置文件。

## 非目标

- 不改变任务、子代理和编辑三个面板的打开/关闭逻辑。
- 不新增背景图片格式、远程图片、拖放导入或图片编辑功能。
- 不修改 Electron 窗口控制、原生标题栏按钮或 Claude runtime。

## 方案选择

### 方案 A：在应用壳层增加全局背景层（采用）

把现有背景伪元素从 `.chat-main` 移到 `.app-root`，让应用路由内容位于背景层之上；将主要外壳和输入/状态表面调整为带主题色的半透明混合色。状态面板开关使用独立 class，并在收起/展开状态分别渲染方向箭头。

优点是沿用现有主进程 IPC、外观状态和 CSS 变量，影响范围集中，所有路由天然共享同一背景。缺点是需要明确处理外壳层级和几个固定表面的透明度。

### 方案 B：给每个页面和面板分别设置背景

在聊天、历史、设置和文件树等组件分别接收背景状态并写入样式。

这种方式会产生重复逻辑，容易出现不同页面背景不一致，也会扩大 React 组件改动范围，因此不采用。

### 方案 C：把图片直接写入 body 的 background

将图片作为 body 背景，再让页面内容自行透明化。

这种方式绕过现有的应用层遮罩与模糊控制，且会让标题栏和 Electron 加载时序更难保持一致，因此不采用。

## 设计细节

### 背景层

- 保留现有 `--bg-chat-image`、`--chat-bg-image-opacity`、`--chat-bg-image-blur` 和 `--chat-bg-overlay-opacity` 变量，避免改变持久化协议和设置页面。
- 在 `.app-root` 创建背景图片层和主题遮罩层，层级低于路由内容，高于基础主题底色。
- `.chat-main` 不再拥有独立图片层；聊天、设置、历史的页面根容器使用透明或半透明表面。
- 标题栏、文件树、输入框、状态栏和弹层使用主题色与透明色混合，既能看到背景又不牺牲对比度。
- 背景缺失时回退到现有主题底色，启动和清除背景的行为不变。

### 状态面板开关

- `ContextBar` 中的按钮改用专用的 `status-panel-toggle-button` class，避开旧容器样式冲突。
- 状态面板收起时显示向上箭头，表示面板会向上展开；展开时显示向下箭头，表示可以收起。
- 保留现有点击处理、localStorage 状态和无障碍标题，不改变任务/子代理/编辑内容的内部交互。

## 测试与验收

- 外观测试确认背景变量应用在 `.app-root`，不再只依赖 `.chat-main`，并保留主进程/预加载边界。
- UI 静态回归测试确认状态面板开关使用独立 class 和两个方向图标。
- 运行相关外观、状态面板测试、`npm run test:protocol`、`npm run build` 和 `git diff --check`。
- 手动验收：分别在深色和浅色主题上传背景，进入聊天、历史和设置页面确认背景贯穿；反复收起/展开状态面板，确认按钮始终有图标且方向正确。
