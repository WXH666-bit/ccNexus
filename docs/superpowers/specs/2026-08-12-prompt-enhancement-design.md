# 提示词增强设计

## 背景

ccNexus 当前已经有提示词增强入口和设置页，但现有实现主要是读取本地正则规则并替换文本，还没有形成用户可理解、可预览、可撤销的提示词增强流程。

本功能采用混合模式：本地增强负责默认的稳定整理，AI 润色只在用户明确点击后执行。设计必须保持 Claude Code 主链路、cc-switch 配置和主会话缓存不受影响。

## 目标

- 在发送前帮助用户把自然语言整理成更清晰、可执行的任务描述。
- 默认使用本地增强，不产生额外模型请求或 Token 消耗。
- 提供可选的 AI 润色，但必须由用户主动触发并明确知道会产生额外消耗。
- 保留原文，支持预览、撤销和最终确认，不自动发送。
- 不修改 Claude Code 配置、cc-switch 配置、settings.json 或项目文件。
- 不改变当前会话的模型、供应商、模式、思考强度、权限流程和缓存链路。

## 非目标

- 不让提示词增强自动执行 Claude Code 任务。
- 不让增强器读取项目文件、执行命令、调用 MCP、使用 Agent 或弹出工具权限请求。
- 不把 AI 润色请求伪装成主聊天消息，也不把它追加到主会话历史。
- 不通过增强器自动添加“跳过权限”“直接写入文件”“始终允许”等行为指令。
- 不在第一版实现自动发送、自动重写用户输入或后台定时润色。

## 现有实现与兼容策略

- 保留现有 `src/utils/promptEnhancer.ts` 作为本地规则能力的基础。
- 当前 `promptEnhancerEnabled` 和 `promptEnhancerRules` 的本地存储格式继续兼容。
- 现有开关只控制用户自定义规则，不控制基础本地整理能力。
- ChatInputBox 中的闪光按钮继续作为入口，但行为从“直接替换文本”改为“生成预览并等待确认”。

## 用户体验

### 入口

- 输入框有文本时启用闪光按钮。
- 只有图片附件而没有文本时禁用按钮。
- 流式对话期间禁用按钮。

### 预览流程

1. 用户点击闪光按钮。
2. 系统先执行本地增强，立即打开预览面板。
3. 面板展示原始提示词和本地增强结果。
4. 用户可以使用本地结果、恢复原文、取消，或主动点击“AI 润色”。
5. AI 润色完成后，面板继续保留原文和本地结果，同时展示 AI 结果。
6. 用户点击“使用此结果”后，结果才回填输入框。
7. 回填不会自动发送，发送仍由用户按 Enter 或点击发送按钮完成。

### AI 润色提示

点击“AI 润色”前显示简短说明：该操作会额外调用当前模型并消耗 Token。AI 润色不是默认行为。

### 错误与取消

- AI 请求失败、超时或网络断开时，显示错误原因，同时保留本地增强结果。
- 用户可以直接使用本地结果，不需要重试 AI。
- 取消 AI 请求不会清除原文或本地结果。
- 关闭预览面板不会改变输入框内容。

## 增强规则

### 本地增强

本地增强由纯文本函数完成，输入相同则输出稳定。处理顺序为：

1. 应用已启用的用户自定义替换规则。
2. 在不改变语义的前提下整理表达。
3. 必要时按“目标、背景、约束、验收标准、输出形式”组织内容。

清晰且简短的提示词不强行扩写。信息不足时保留信息不足，不编造技术栈、文件名、功能需求或验收条件。

文件路径、命令、URL、代码块、专有名词和用户明确给出的原文必须保留。自定义规则中的非法正则或未完成规则必须被忽略，不能阻止正常发送。

### AI 润色

AI 润色只接收用户当前草稿及本地增强结果，并要求模型只返回改写后的提示词，不执行任务、不调用工具、不输出解释性元数据。

AI 润色必须保留用户原意，不得新增权限绕过、自动写入、自动执行或其他行为指令。模型返回空文本或无法解析时视为失败。

## 架构与边界

### Renderer

- `src/utils/promptEnhancer.ts`：纯本地增强、规则读取、规则校验和文本结果校验。
- `src/components/ChatInputBox/PromptEnhanceDialog.tsx`：预览、状态切换、按钮和错误提示。
- `src/components/ChatInputBox/index.tsx`：只维护草稿和预览状态，并在确认后回填文本。
- `src/components/ChatInputBox/ButtonArea.tsx`：只负责触发增强入口，不承担增强逻辑。

### AI 调用隔离

AI 润色通过独立的桌面桥接操作执行，不复用当前活跃聊天查询和主会话历史。该操作必须使用无工具、无文件上下文、无 Agent、无 MCP、无权限回调的短生命周期请求。

它可以读取当前有效模型配置来完成请求，但不得写入供应商配置、Claude Code 配置或 cc-switch 配置。主 `chatController` 的会话状态和正常消息流不得因该请求发生变化。

### 用量与缓存

- 本地增强不产生模型请求，因此不影响主聊天缓存和用量。
- AI 润色是独立请求，不能声称“零消耗”；界面必须在触发前提示额外 Token。
- 如果 SDK 返回使用量，AI 润色使用量应作为独立的 `prompt-enhancement` 事件进入用量统计，不能混入主会话消息。
- 主会话的缓存上下文、消息顺序和 SDK 查询参数不因 AI 润色改变。

## 状态模型

预览功能至少维护以下状态：

- `originalText`：打开预览时的原始草稿。
- `localResult`：本地增强结果。
- `aiResult`：可选的 AI 润色结果。
- `selectedResult`：当前准备回填的结果。
- `aiStatus`：`idle`、`loading`、`success` 或 `error`。
- `aiError`：面向用户的错误信息。

确认回填只更新输入框草稿，不调用发送函数；取消和关闭只销毁预览状态。

## 测试与验收

### 单元测试

- 空文本和空白文本不被增强。
- 自定义规则按顺序执行。
- 非法正则被忽略，正常文本仍可发送。
- 文件路径、命令、URL 和代码块保持完整。
- 清晰短文本不会被无意义扩写。
- 本地增强结果具有稳定性和可重复性。

### 交互测试

- 闪光按钮在无文本、流式状态下正确禁用。
- 点击后只打开预览，不自动发送。
- 本地结果可使用、原文可恢复、取消不改变草稿。
- AI 润色加载、成功、失败和取消状态正确。
- AI 失败后仍可以使用本地结果。

### 集成回归

- 主聊天消息仍按原路径发送。
- 当前模式、模型、供应商、思考强度和权限流程不改变。
- 不写入 Claude Code 或 cc-switch 配置。
- 主会话历史不出现 AI 润色中间请求。
- `npm.cmd run test:protocol`、`npx.cmd tsc --noEmit` 和 `npm.cmd run build` 通过。
- 使用桌面应用手动验证本地增强、AI 润色和恢复原文流程。

## 第一版验收标准

用户可以在输入框中点击提示词增强，先看到稳定的本地增强预览；用户主动点击 AI 润色时才发起独立请求；用户确认后内容才回填且不会自动发送。整个过程不修改 Claude Code 或 cc-switch 配置，不触发工具权限，不污染主会话，并对 AI 润色的额外用量作出明确提示。
